## 范例一：方法类（Skill Training with Corruption and Reconstruction Loop）

开头与背景表，注意表格格子里是完整句子：

```markdown
训练技能库而非权重，文本空间的"扩散式"自监督：Skill Training with Corruption and Reconstruction Loop
Paper：https://arxiv.org/abs/2607.27557
Github：https://github.com/skilltraining-project/skill-training

## 一、背景与动机

LLM 在专业领域（如短剧编剧）常不及人类专家。外部 skill 是比微调更轻、更可审计的路线，但 skill 从哪来始终是瓶颈：

| 路线 | 问题 |
| --- | --- |
| 参数微调 | 最强的模型大多闭源，开源大模型微调成本也很高，还容易发生灾难性遗忘；学到的能力被固化在某个 checkpoint 的权重里，既无法检查学到了什么、也无法纠正学错的部分，换一个底座模型就要重新训练 |
| 直接总结优秀样例 | 人类专业作品里只有"做对的部分"，不包含新手常犯的错误，因此总结出的规则只能告诉 agent 好作品长什么样，却无法告诉它自己具体错在哪里 |

本文的目标：冻结模型参数、不要额外标注和外部 reward，直接从已有的高质量人类作品中自动学出 skill 库。

## 二、方法总览

![Figure 1 框架总览](images/skill_training/fig1_overview.png)

借鉴扩散模型的"加噪—去噪"：把人类剧本当作干净数据，压缩成大纲（corruption），让 agent 从大纲重建剧本（forward），再用"重建稿 vs 原作"的语义差距作为 loss，反传更新 skill 库（backward）。skill 库就是可训练参数，loss agent 相当于 loss 函数，backward agent 相当于优化器，linter 相当于正则项。
```

核心小节，"关键问题 → 解法"写法，小节标题括注解决的问题：

```markdown
4.3 MoE 路由 + Linter 正则（解决"库膨胀与过拟合"）

* 卡片按 MoE 拓扑分进三个专家文件夹：通用原则 / 技法 / 题材惯例，生成时按需读取（23 张卡中位数只读 9 张）；
* 关键问题：早期不设限，库开始疯狂记忆案例，最长一张卡长到 2500 行，读起来像"每本小说的事故日志"；
* 解法：Linter 作为硬正则，卡片正文 ≤ 1200 tokens、description ≤ 200 tokens，禁止集数编号和案例式措辞，每次 commit 前检查。硬容量逼 agent 抽象出通用规则。

4.4 数据并行 Micro-step（解决"信号稀释"）

所有小说基于同一个库快照并行前向，得到一批 loss 报告。整批喂给 backward agent 会导致编辑含糊，因此先按每 4 本小说分层 reduce 成共性摘要，再由短生命周期 agent 串行逐份消费、每步只做少量编辑。后面的 step 面对的是已被改过的库，prompt 中会显式告知这个"时间差"，要求先对照当前库验证再落地（类似 stale gradient）。
```

效果，每条"小标题：完整句子"，反直觉结论要给出原因：

```markdown
* 主结果：+Ours 只有 23 张卡，6 个方向性指标全部显著优于 Base，硬切结尾 34% → 67%、冷开场 52% → 74%，均超过人类原作。+Distill 攒了 131 张卡、11 万 tokens，集级结构却毫无提升——专业剧本里没有业余错误，示例和蒸馏都教不会 agent 它自己错在哪。
* 跨模型迁移：Sonnet 训出的库直接给 Kimi、Opus 使用同样有效。反直觉的是，Opus 用 Sonnet 的库比用自己训的库更好（5/6 指标）。原因在于学习是误差驱动的：Opus 基础错误少，写出的定量规则也少；Sonnet 错得多，被迫攒出一套严格硬约束。由此引出"弱模型挖规则、强模型执行"的实用范式。
```

## 范例二：benchmark 类（LivingScreen）

benchmark 论文的"核心"是任务形式化本身。公式前后各有一句话说明它在做什么：

```markdown
## 二、★ 核心：Living-Screen-Native POMDP ★

标准 GUI agent 被建模为 POMDP，状态只在 agent 行动时变化 $s_{t+1} \sim T(\cdot \mid s_t, a_t)$，每一步获得一张截图 $o_t \sim O(\cdot \mid s_t)$。这种"离散时间、由 agent 驱动"的形式无法描述含视频的屏幕，本文做了两处修改。

（Δ2）由 agent 发起的观察。 把逐点采样的观察 $o_t \sim O(\cdot \mid s_t)$ 换成由动作参数化的观察：

$$o_k \sim O\!\left(\cdot \mid \{\, s(t) : t \in W(a_k) \,\}\right)$$

$W(a_k)$ 是由动作决定的时间窗口，$O$ 提取这段窗口内屏幕上实际渲染的内容。也就是说，看一张截图还是录一段视频、录多长、用什么帧率，都由 agent 自己决定。获取信息因此成为一个有成本的内生决策，而不是外部输入的数据流。
```

分析章节，用一段话讲清一个发现，并联系到已有理论：

```markdown
5.1 人类会"扫一眼再决定"，模型不会

按每个视频的观看比例 r 分为四类：跳过（0%）、扫一眼（≤10%）、部分观看（10%–80%）、看完（>80%）。……人类与所有模型的差别则集中在一点：人类有 52.0% 的观察落在"扫一眼"，而没有任何模型超过 26%。人类会先花很少的注意力判断一个视频值不值得看，再决定是否深入观看，这与信息觅食理论中"低成本侦察 + 选择性深度消费"的策略一致。模型缺少这个侦察步骤，一旦开始看就看很久，同时跳过的视频又比人类多，等于注意力在不该花的地方花多了、在该花的地方花少了。
```

## 范例三：带公式的方法类（FocusGUI）

背景表也可以列"作者的实证发现"，用完整句子写清数字和含义：

```markdown
| 现象 | 具体表现 |
| --- | --- |
| 相关性随步骤切换 | 决定动作的主导模态在 45.3% 的相邻步骤之间发生切换，94.0% 的 episode 至少切换一次。上一步关键的信号，到下一步可能就变成了干扰 |
| 决定性证据非常稀疏 | 目标元素的面积中位数只占屏幕的 0.87%，一步之内视频内容的变化中位数只有 7.41% |
```

核心小节：先说为什么要这样设计，再给公式，最后解释符号和效果：

```markdown
3.2 随步骤自适应的通道优先级（解决"相关性随步骤切换"）

融合后的表示里无法定义优先级，所以先把观察拆成可分离的感知通道 $\{x_t^{(m)}\}$，包括各个模态、一个屏幕空间通道和底座的整体隐状态。……一个通道有没有用，不仅取决于它本身的内容，还取决于当前的任务状态，因此用整体观察的表示得到决策参考 $q_t = P_q(e_t^{(\text{all})})$，再计算每个通道与它的匹配度并归一化：

$$s_t^{(m)} = v^\top \tanh\!\left(W_e\big(e_t^{(m)} + r_m\big) + W_q q_t\right), \qquad \alpha_t^{(m)} = \frac{\exp(s_t^{(m)}/\tau)}{\sum_{j}\exp(s_t^{(j)}/\tau)}$$

$r_m$ 是可学习的通道身份 embedding，$\tau$ 是温度。通道表示和决策参考每一步都重新计算，所以各信息源的相对权重可以随任务推进而变化。
```

效果中的"对照"写法，说明结果为什么支持论文的论点：

```markdown
* 越往后优势越大：如果 Sequential Distraction 成立，有效的方法应当随轨迹变长与底座拉开差距，而不是保持固定的领先幅度。冻结的 Qwen2.5-Omni 的 TM 从第一步的 64.79 掉到第四步以后的 32.79，只保留了一半；FocusGUI 保留了 86.8%。Instant 类任务是一个反例对照：前两步历史还很少时，两者没有显著差异，历史积累起来后 FocusGUI 才拉开差距，这说明它针对的确实是误差累积。
```
